## 功能节点与精确触发条件

实现：`scripts/handoff_gate.py`、`Controller.begin_handoff_reconciliation` / `reconcile_handoff`，worker schema 增加 handoffGate。

| 节点 | 触发条件 | 动作 |
| --- | --- | --- |
| 登记迁移 | leader 取得真实 operationId 并提供明确目标契约 | 持久化 pending；已有未决操作不可覆盖 |
| 回执核对 | sourceThreadId、operationId、success、destinationThreadId 全部吻合 | 继续观察核验；不凭 success 放行 |
| Git 核对 | root/cwd/branch/HEAD、clean、leader_git 全部吻合 | Controller 再直接读取 Git root/common-dir/branch/HEAD/dirty |
| 附件核对 | host_artifacts 来源且清单与目标契约精确一致 | 才视为附件通过；unknown 拒绝 |
| 模型核对 | 目标宿主配置元数据或目标 turn_context，绑定目标 threadId 和 operationId，model/thinking 与契约精确相同 | 才允许通过；请求参数、prompt、自述、源 turn 不接受 |
| 时效检查 | observation 时间距当前 0–300 秒 | 陈旧、未来或无时间证据拒绝；继续操作前需重新观察 |
| 通过 | 所有证据成立且直接 Git 核验成功 | 重绑目标 threadId/root/branch，activityRevision 前进，状态回到 validating |
| 旧证据失效 | 首次通过迁移门禁 | 清除旧 hostObservation、dispatchIntent、report、acceptance、verificationPlan、stop 等证据；启动需重新验证 |
| 失败/unknown | 任一字段不符、Git 无法读取或证据缺失 | 持久化 blocked，不修改 worker 到目标身份 |
| 后续派发/恢复派发 | _ensure_external_action_allowed | 再检查迁移门禁、时效及 worker 身份；阻塞时无宿主发送 |
| 返工/独立验收/集成 | _review_worker | 同样检查迁移门禁 |
| 保存失败 | 任一门禁状态落盘失败 | 回滚内存；不继续操作 |

该模块不主动调用 handoff。leader 使用原生工具迁移后，必须在继续派发前登记并核对；尚未实现宿主迁移调用与控制器 pending 写入的一体化事务。原生工具绕过 Controller 的调用也不会被 Python 自动拦截。

模型/附件观察是 leader 提供的可信控制面输入，来源标签不是签名。真实环境必须按目标身份从宿主读取，禁止将源字段换个 threadId 伪造目标观察。现有接口不能提供目标运行配置时应继续阻塞。
