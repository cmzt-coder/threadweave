## 范围与结论

本轮补齐 A 桌面 leader 桥接的等待、managed worktree 创建/附加/状态查询/归档、聊天归档方法。结合前一轮真实双 worker 的报告、独立验收、返工、失败阻断恢复及串行集成证据，构成 T06 的桌面桥接验收。Python 负责持久请求与回读，真实桌面工具由获授权的 leader/worker 执行；这不代表 Python 可自行连接桌面或无人值守运行。

本轮是无 tracked 文件改动的生命周期探针：`filesChanged=[]`、报告 HEAD 为基线。控制器执行实际分支验收与集成验收，但没有新代码 merge；前一轮双 worker 才是开发与串行合并证据。O03 真实越界负例、O04 主动进程崩溃、O07 实际串行资源项目仍未验证。

## 实现

- `scripts/desktop_lifecycle_bridge.py`：`DesktopLifecycleBridgeAdapter`，有界等待与 cursor、资源操作精确 allowlist、原始工具响应回填及新进程回读。
- `scripts/desktop_bridge.py`：生命周期请求纳入同一持久账本；先 prepare，再 claim，再执行真实工具，最后 complete。
- `scripts/controller.py`：`confirm_stop_from_wait` 仅接受新鲜、同任务、idle/completed、同 turn final_answer 且回显当前报告完整 reportSha 的等待回执；`archive_worker_host` 要求已集成、停止修订一致和用户授权。
- `scripts/host_adapter.py`：新增默认拒绝的附加、worktree 状态查询和聊天归档接口，保持旧实现兼容。

`unknown` 不自动重试，终态不可覆盖，同一操作回放不重新调用宿主。worktree 原始对象保持完整：异步 operationId 不当成路径；归档 `queued` 只代表受理。

迁移后的清理 turn 实际配置为 `ccs-gf-gpt/gpt-6.1-sol / high`。leader 发送时未覆盖模型，宿主没有继承原配置；即使 prompt 明确要求保持模型也不能保证执行配置。这违反本轮禁止换模型要求，已单独记录，不能把迁移后的清理当作 deepseek 验收。发现后未扩大任务，只完成已发出的资源清理。

后续门禁：handoff 后将目标视为新身份，核对返回 destinationThreadId、cwd、分支、附件和模型；未核对模型前不发送任务。需要保留模型时，使用支持显式 model/thinking 的宿主调用并验证 turn_context；当前发送桥接不支持此覆盖，不得伪称已自动保证。该 handoff 模型保持问题列为后续独立事项，不影响迁移前 create/attach/archive/wait 的实际证据。
