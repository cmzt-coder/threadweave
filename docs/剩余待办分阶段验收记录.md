## 阶段 1：契约审查结果

依据：当前工具完整声明、`desktop_bridge.py`、`desktop_lifecycle_bridge.py`、`managed_cleanup.py`、`cleanup_apply.py`、`handoff_gate.py`、`controller.py`。

| 事实 | 可信来源 | 当前结论 |
| --- | --- | --- |
| 项目 runId/role/attempt/taskRevision | 项目创建请求与持久化账本 | 不应声称是宿主固有字段；账本绑定可证明项目关联，但不能单独证明资源实际归属 |
| 实际资源路径与创建结果 | 原始宿主创建/附加回执、当前附件身份及 Git root/commonDir | 需精确关联，不能仅凭路径前缀推断 |
| owner、primary/shared/受保护状态 | 宿主明确观察或权威资源操作检查 | archive 的拒绝保护是执行时保障，不等于事前可观察事实；当前清理门禁的字段映射尚未建立 |
| Git HEAD/branch/clean、已合入、报告完整性 | leader 直接 Git/文件哈希 | 可本地验证，不能证明聊天停止或模型 |
| worker 停止 | 新鲜目标状态、同 turn 完成与 final、当前任务关联 | timeout/notLoaded/归档状态不能代替停止证据 |
| 迁移完成 | operationId 绑定的宿主成功回执 | 不等于目标模型、附件保持 |
| 实际 model/thinking | 目标自身的新运行上下文或权威目标元数据 | 请求值、源历史及 worker 自述均不充分 |
| 目标附件完整清单 | 目标范围的宿主资源观察 | 当前 list_artifacts 仅调用者范围，不假定可以查询其他聊天 |

审查决定：不把“缺少宿主同名字段”直接解释成“必须等待宿主实现这些字段”。可以设计创建账本与原始资源回执的证据映射，但须另行验证资源身份、调用范围及保护边界；本阶段不引入未经证明的映射，不删除现有保护。桥接哈希防误关联，不提供宿主签名或对抗恶意本地写入者的证明。
