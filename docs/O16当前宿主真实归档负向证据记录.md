## 事实解释与边界

这说明当前宿主把该次 `create_worktree` 返回的专用 worktree 视为当前任务的 primary checkout，即使 Git 层显示为 detached、非主 checkout。此前历史测试也观察到 primary checkout 会被归档工具拒绝；本次是当前宿主的新鲜真实负向证据，而不是 fixture。

该错误不支持以下任何结论：

- 不能证明 ownerThreadId、isPrimary 字段在附件 payload 中可用；
- 不能证明 primary/shared/owner 的完整拒绝矩阵；
- 不能证明当前调用者已获得可归档的非 primary 资源；
- 不能把失败拒绝当作 O16 正向归档完成。

`scripts/host_archive_guard.py` 对失败 archive 原始 envelope 返回 `blocked`，不会生成 `hostArchiveCompleted=true`。这是预期的 fail-closed 行为。

## 当前资源处置

专用 worktree 当前保留在宿主管理目录中，状态为 detached、clean、无未提交成果。由于宿主明确称其为 primary checkout，本轮不执行本地强制删除，也不尝试通过绕过宿主保护来清理。后续需要宿主提供 detach/切回 Local 的受控入口，或确认该资源不再被当前任务视为 primary 后再处理。
