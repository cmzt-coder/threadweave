## O01 验证执行器接口

`verify.execute_plan(plan, repo_root, context)` 返回可 JSON 序列化结果；`verify.plan_hash(plan)` 返回规范化 JSON SHA256。
plan 为字典：`version:1, steps:[{id, argv:[str], cwd:'.', timeoutSeconds:positive, expectedExitCode:0, dependsOn:[id], continueOnFailure:bool}]`。默认失败后跳过后续步骤；显式 continueOnFailure 允许后续无依赖步骤继续，依赖失败始终跳过。禁止 shell 字符串；cwd 必须在 repo_root 内。先校验整个计划再执行，拒绝空计划、重复 ID、未知依赖与循环。
context 原样绑定：`runId, role, attempt, taskRevision, stage ('worker'|'integration'), head`。结果包含 `status ('passed'|'failed'), context, planHash, steps, startedAt, finishedAt`；步骤包含 id/status/exitCode，失败和 timeout 影响总结果，摘要有界。repo_root 应为实际 Git checkout；执行前后 HEAD/工作区状态变化应拒绝成功。超时终止进程组，测试真实子进程。CLI `--plan PATH --repo PATH --context PATH`，成功退出 0，其余非零。
leader 的 `Controller.verify_worker(role,attempt,plan)` 独立核验 worker 停止证据、实际 Git 身份/tip/base、执行并持久化 acceptance。`Controller.integrate(role,attempt,merge_commit,verification=None,plan=None)` 不再信任 verification 字符串；要求 worker acceptance 仍有效；核验实际集成 HEAD、worker tip 已合入及集成前后证据，独立执行集成 plan。失败持久化 integrationBlocked 并阻断后续；`Controller.recover_integration(plan)` 在当前集成 HEAD 重验通过后显式解除。拒绝旧字符串冒充成功；旧状态可读，但需补验。

## O02 报告接口

`report.validate_report(payload, expected, observed)` 返回校验后的报告字典，失败抛 ValueError（含 JSON 字段路径）。payload 必含 `runId, role, attempt, threadId, branch, head, reportSha, taskRevision, baseIsAncestor, filesChanged, testsRun, selfReportedVerification, contractChanges, knownRisks`。commitSha 如存在必须等于 head；列表类型严格检查。expected 是同名身份字段的预期值；observed 含 `head, branch, baseIsAncestor, filesChanged`，须由 leader 实际 Git 采集，不能从 payload 复制；除去顺序后文件清单须相等。与 O03 分工：此模块验证清单真实性，scope 判断路径是否获准。
`report.report_hash(payload)` 对去掉 reportSha/acceptedAt 的规范化 JSON 做 SHA256；reportSha 必须等于该值，不是 Markdown 的哈希。测试与模板保持一致，旧格式通过显式重报迁移，不默许绕过新门禁。

## O03/O07 范围接口

`scope.check_reservations(workers, repo_root, serialized_resources=None)` 返回 errors 字符串列表，空列表通过。workers 为当前有效任务，每项含 role,attempt,ownedPaths:[str],scopeExceptions:[str]；后两个列表是仓库相对 glob，* 不跨 /，** 可跨目录。缺声明不是隐式拥有整个仓库；leader 保持未启用声明的旧 run 兼容，但启用后团队任务均须声明。
`scope.check_changes(changed_paths, owned_paths, scope_exceptions=None)` 返回 errors 字符串列表；changed_paths 含重命名旧/新路径。匹配使用相同规范；拒绝绝对/父目录穿越/空路径。预留不能只展开现有文件，模式相交不能证明为空时保守拒绝并解释，防新增文件遗漏。serialized_resources 为 `[{name, paths:[glob]}]`；两个任务命中同组即冲突，哪怕实际文件不同。repo_root 内符号链接越界要拒绝。
leader 从项目根 threadweave.config.json 可选读取 `serializedResources`；无配置为空，不在本轮实现 setup 配置。worker declarations 可选扩展 schema；新 run 有范围契约时先检查全部有效 worker 再发消息，集成前实际 Git diff 复核。

## O04 恢复建议接口

`next_actions.build_next_actions(state, observations=None)` 返回 `{runId, actions:[{action, worker, reason, ...}], ...}`；observations 使用 recovery.build_recovery_plan 与 cleanup.build_cleanup_plan 已有格式。未知/pending dispatch 优先 revalidate，缺外部观察不得建议直接发消息或创建资源。完成且 cleanup complete 时无需动作。初版不新增 lost/resume 状态。
CLI 新增 `next --repo . [--run ID] [--observations FILE]`；无 run 用 latest_incomplete_run。严格只读，不调用宿主或执行删除；错误输入给明确非零退出。

## O05 / 回归 / 文档

leader 实现 maxReworkPerWorker 默认 2：有效 attempt、reported 状态、run 可操作且非停止中才允许。超限不改任务状态、计数、activityRevision，不发送消息；独立审计记录拒绝，leader 决策后再处理。返工使旧 report/acceptance 失效。
regression worker 使用真实临时 Git 仓库和 FakeAdapter 只验证控制器本地逻辑，覆盖 A 验收失败阻断 B、磁盘恢复后继续阻断、显式重验恢复、旧 taskRevision/SHA/计划失效、返工超限等。不得修改 controller；接口缺失先记录失败证据，完成提交后由 leader 接线使测试通过。
文档 worker 同步 JSON 字段/验证契约与 O17 场景判定；一 worker 一 worktree 不变，前后端一起交付并不等于必须共享目录。不要宣称真实 HostAdapter 已实现。
