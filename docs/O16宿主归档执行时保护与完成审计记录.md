# O16 宿主归档执行时保护与完成审计记录

日期：2026-11-16。范围：在不依赖宿主返回 `ownerThreadId` 等未知字段的前提下，审计一次已执行的 `archive_worktree` 是否完成，并明确保护责任来自哪里。状态：本地实现与受控完成审计通过；当前真实宿主正向验收仍未完成。

## 设计结论

当前宿主工具声明提供了两个可用的边界：

1. `list_artifacts({})` 只返回当前调用聊天的附件，不接受目标 threadId 参数。
2. `archive_worktree({root})` 只接受当前聊天附件的 identityKey，并在执行时拒绝 primary、workspace-protected、shared、含初始化 submodule 或 embedded Git 的资源。

因此不再把“缺少 payload 所有权字段”强行映射成安全字段，而是采用独立的三段证据：

```text
项目创建账本 + 当前调用者活动附件
              ↓
宿主 archive_worktree 执行时保护
              ↓
queued 回执 + archived_worktree + 目录/Git 注册消失
```

这不是“调用前已经观察到所有权”，也不把 `queued` 当成删除完成。`queued` 只证明宿主受理，最终完成必须由新鲜 `list_artifacts` 和本地资源观察共同证明。

## 新模块

新增 `scripts/host_archive_guard.py`，提供 `verify_host_archive(spec, now=None)` 和 CLI：

```sh
python3 scripts/host_archive_guard.py /absolute/archive-evidence.json
```

输入清单要求：

- `protectionPolicy` 必须精确为 `host_archive_worktree_execution`。
- 仓库、worktree 为规范化绝对路径。
- `runId/role/attempt/taskRevision` 显式绑定。
- 创建操作、归档前 `list_artifacts`、归档操作、归档后 `list_artifacts` 的 operation 和绝对原始结果路径。
- `archiveRequestSha` 必须精确等于归档账本请求哈希。

归档前必须同时满足：

- 创建账本和当前调用者附件通过 `resource_provenance` 来源映射。
- 创建来源是该仓库，活动 worktree identityKey、payload host/root/workspaceRoot 精确匹配。
- 清单在 30 秒内且不早于创建。
- 当前调用者清单只有精确资源，不以路径前缀或名称猜测。

归档操作必须满足：

- 账本终态成功，method 精确为 `mcp__codex_app__archive_worktree`。
- 请求参数精确为 `{"root": "<exact worktree>"}`。
- 原始结果哈希和 metadata 与账本一致。
- 只接受历史实证的 `{"type": "queued"}`；该结果只代表受理，不增加 `hostArchiveCompleted`。

归档完成必须同时满足：

- 归档后 `list_artifacts` 是同一 run/role/attempt/taskRevision 的新鲜观察。
- 目标不再以 active worktree 出现。
- 目标以唯一 `archived_worktree` 出现，嵌套 payload 的 host/root/workspaceRoot 精确匹配，`sourceGitRoot` 精确等于仓库。
- 归档时间和完成清单时间有序，且完成清单距当前为 0–30 秒。
- worktree 路径不存在；`git worktree list --porcelain` 不再包含该路径；源仓库 Git root 仍可观察。

## 功能节点与精确触发条件

| 节点 | 成功条件 | 阻断条件 | 输出/边界 |
| --- | --- | --- | --- |
| `verify_host_archive` 入口 | 清单为对象且 policy 精确 | 缺 policy、路径非规范化、版本非整数、绑定缺失 | `blocked`，不读宿主、不删资源 |
| 归档前来源 | `resource_provenance` 返回 `associated`，当前附件为 active，proof 绑定同一 operation | 创建账本/原始回执错误、资源不匹配、清单过期、pre 已是 archived | `callerInventoryScopeVerified=false` |
| 宿主归档受理 | 原始 MCP 成功、method/参数/请求哈希/结果哈希匹配，结果精确 `queued` | error envelope、未知格式、旧/新 operation、批准请求哈希不一致 | 仅受理，不宣告完成 |
| 归档后附件 | 唯一 `archived_worktree`，active 为零，payload identity 完整 | 仍 active、缺失、重复、host/root/source 错误、清单过期或乱序 | 必须继续 blocked |
| 本地完成观察 | 目录不存在且 Git worktree 注册不存在，源仓库仍在 | 路径残留、Git 注册残留、仓库不可读 | 不能把 `queued` 当完成 |
| 结果输出 | `host_archive_verified`，`completionVerified=true` | 任一证据不完整 | `cleanupEligible=false` 恒定 |

## 输出与责任边界

成功输出的固定安全字段：

- `readOnly=true`：本模块没有调用宿主或删除资源。
- `deletionPerformed=false`：本模块不执行清理。
- `cleanupEligible=false`：完成审计不能自动为下一次清理授权。
- `completionVerified=true`、`hostArchiveCompleted=true`：只描述本次外部归档结果。
- `preObservableProtection=false`：没有声称在调用前观察到 primary/shared/owner。
- `protectionBasis=host_archive_worktree_execution`：保护来自宿主归档工具的当前调用者作用域和执行时拒绝规则。
- `unknown` 保留 `ownerThreadId/isPrimary/isShared/callingThreadId`。

调用前所有权字段仍未知；本模块不证明资源属于哪个聊天，也不证明调用者身份。它只证明当前调用者附件清单、一次绑定归档请求和归档完成结果的关系。若宿主实际接受了不应删除的 primary/shared 资源，本审计不能弥补宿主保护失效；后续应按发现的问题单独评审。
