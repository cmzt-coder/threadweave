# 宿主观察缺口与恢复验收条件

核对日期：2026-11-16。本次仅审阅当前可调用工具的完整声明与项目门禁代码，没有新增聊天、迁移、归档或删除操作。

## 接口核对结论

| 接口 | 声明支持 | 未承诺的能力及影响 |
| --- | --- | --- |
| `list_artifacts({})` | 当前调用聊天的附件类型、身份、payload、创建时间 | 不接受目标 threadId；不承诺 payload 的 ownerThreadId/runId/isPrimary/isShared。不能据此关闭 O16 |
| `archive_worktree({root})` | 按本聊天附件 identityKey 归档；宿主拒绝 primary、受保护、shared 等资源 | 宿主拒绝机制不是调用前可信所有权观察，也不是执行成功的证据 |
| `read_thread` | 目标聊天近期状态、turn 摘要及可选输出 | 不承诺目标实际 model/thinking 或完整附件清单。继承历史不能代替迁移后的运行证据 |
| `handoff_thread` | 迁移其他聊天，返回 operationId/revision，另查状态 | 迁移完成不自动证明目标保持模型及附件；不能迁移调用者自身 |
| `wait_threads` | 按目标聊天等待完成或需处理，并返回状态 | 不承诺附件归属及运行模型；归档聊天的 notLoaded 不等价于新鲜 idle |

上述是当前工具声明的能力边界，不表示所有宿主版本永远无法提供额外字段。历史实测空附件与 notLoaded 已记录在“剩余待办逐项推进记录”，本次没有重复探测。

## O16 恢复条件与验收顺序

触发条件：宿主提供可查询目标资源归属及保护状态的可信接口，或提供可明确映射到现有门禁的、文档化的等价证据。

1. 先保存真实原始回执与接口版本，核对字段语义；当前脚本的字段名是项目放行契约，不是宿主已承诺的 schema。
2. 如需映射，先审查并实现适配；禁止手工补写“安全”字段冒充宿主观察。
3. 在获得专用验收聊天授权后，准备可归档的非 primary、非 shared 专用资源；验证目标精确停止、身份绑定与 30 秒观察时效。
4. 复核 Git 精确清理计划，再调用宿主归档。核对完成回执、资源归档状态及保全成果，不能仅凭请求已提交标记删除成功。
5. 保留未知归属、活动状态、计划漂移、宿主拒绝的负向用例。

## H01 恢复条件与验收顺序

触发条件：能读取迁移后目标自身的实际 model/thinking，以及目标附件的可信完整清单。

1. 先证明观察来自目标的新运行上下文或权威元数据，而非源聊天继承历史、请求参数或 worker 自述。
2. 预先持久化迁移意图；调用后绑定真实 operationId，保留失败或未决状态。
3. 获取成功回执，按目标 threadId/operationId 绑定运行观察；独立核对 Git root/commonDir/branch/HEAD/clean。
4. 在 300 秒观察有效期内核对附件身份和指定模型；通过后重新启动验证，再允许正式任务派发。
5. 观察缺失、过期、模型变化或附件不符继续拒绝。正向验收及专用资源清理均留原始证据。
