## 当前宿主能力矩阵

| 能力 | 结论 | 证据与边界 |
| --- | --- | --- |
| `list_projects` | 支持 | 返回唯一本仓库 Git 项目，projectId 与 canonical path 匹配 |
| `create_thread` + project worktree | 支持 | 创建两个真实 worker 线程和独立 managed worktree |
| 异步创建结果解析 | 支持但有间接性 | 首次返回 `clientThreadId`，随后通过 `list_threads` 的 exact title/project/cwd/summary 唯一解析真实 threadId；没有专门 thread-creation status resolver |
| `send_message_to_thread` | 支持 | STARTED、ACK、COMPLETE 双向往返成功 |
| `wait_threads` | 支持 | 返回 turnCompleted / idle，可用于有界事件等待 |
| `read_thread` | 可用但未使用 | 本次启动证据由 worker 消息与 leader 直接 Git 检查获得，无需展开完整 transcript |
| `set_thread_archived` | 支持 | 两个 worker 均归档成功 |
| task-owned worktree 的 host cleanup API | 受限 | `archive_worktree` 不能从 leader 访问其他 task 拥有的 worktree；`attach_worktree` 同样被拒绝 |
| `git worktree remove` 安全兜底 | 本地支持 | 仅在已合并、干净、报告外置、worker idle、无子模块时非强制删除 |
| 取消、异步失败/超时、替换 | 未验证 | 本轮只覆盖正向成功路径 |
| `update_plan` | leader 未暴露 | leader 使用 `.threadweave/<run-id>/state.md` 降级 |

## 尚未验证的故障路径

| 场景 | 状态 | 后续验证方式 |
| --- | --- | --- |
| 多/零 projectId 匹配 | 未动态验证 | 使用受控适配环境确认不创建 worker |
| 异步创建失败、超时、取消 | 未验证 | 根据实际返回与可用的状态接口检查真实 ID 出现前不误用 client ID |
| 错误目录、仓库、基线被 leader 拒绝 | 仅验证正常路径 | 注入错误启动证据，确认不派发正式任务 |
| 不可用显式模型 | 未验证 | 验证创建前阻塞且无静默替换 |
| 缺失可选工具的降级 | 仅文档审查 | 在隐藏对应工具的环境验证文件计划与有限状态检查 |
| 运行中停滞、每角色一次替换、用户取消 | 未验证 | 检查旧 worker 停止证据、尝试上限与成果保留 |
| managed worktree 正常 API 清理 | 宿主 API 不可用 | 需要宿主提供可从 leader 管理 worker-owned worktree 的接口 |
