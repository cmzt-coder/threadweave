# 第一轮执行闭环验证记录

日期：2026-11-12。
结论：协议与模板实现完成；本地 Git 与静态检查通过；真实双 worker 冒烟验证受阻，尚未通过。

## 已实现

- 通过项目发现匹配真实 projectId 与主机，不接受路径 ID 或模糊匹配。
- 初始化状态区分 creating、pending、validating 和 ready；真实 threadId 与异步标识独立记录。
- 全部 worker ready 后才派发；核验实际路径、Git 身份、分支、基线和干净状态。
- 默认继承模型配置；显式覆盖先验证目标主机支持情况；不宣称不可观察的实际配置值。
- 支持文件计划与有限状态检查降级，默认不创建 heartbeat。
- 记录直接用户授权及消息往返范围；超时不等于停止，归档不等于取消。
- 清理前保留报告和成果；失败或不支持的资源处理单独记录，禁止虚报完成。

这些是 Skill 协议和模板约束，尚无自动执行状态机、schema 校验器或 Codex API 适配器。不能将文档中的检查条件称为程序已经自动强制执行的保障。

## 可重复的本地检查

在项目根目录运行：

```bash
python3 tests/git_protocol_smoke.py
git diff --check
git check-ignore .DS_Store
```

脚本使用 Python 标准库，在临时目录创建独立测试仓库，模拟两个 worktree 的 Git 操作；不调用真实线程 API，不操作项目分支，也不模拟远端异步生命周期。

本次输出：36 项断言全部通过。覆盖如下：

| 检查 | 结果与边界 |
| --- | --- |
| detached HEAD 与显式建分支 | 两个临时 worktree 均先 detached，再建立唯一分支，核验 clean 与相同基线 |
| Git 身份与隔离 | common directory 一致、三个 worktree 根目录不同；外部仓库身份可区分 |
| 路径别名 | symlink 解析后识别为同一目录，证明不能仅比较路径字符串 |
| 分支冲突 | Git 拒绝已有分支名，原分支 SHA 不变 |
| 脏目录 | 未跟踪文件可见；普通 worktree remove 失败且文件保留 |
| 基线与报告 | 提交后能观察 HEAD 变化；报告被忽略但可通过 ignored 文件检查发现 |
| 串行集成 | 依次合并两条分支，每次核验相应文件，最终两个结果均存在 |
| 清理与报告保留 | 删除测试 worktree 后，外部复制的报告仍存在；最终仅剩主 checkout |
| 静态契约 | 六阶段标题、引用文件存在、运行文档无固定旧模型和路径 projectId 占位符、代码围栏配对 |

`git diff --check` 通过，`.DS_Store` 命中忽略规则。静态契约检查不能证明模型执行时必然遵守协议。

## 当前环境的实际检查

已只读调用当前应用的 `list_projects`：返回列表没有与本仓库根目录匹配的已登记 Git 项目；已登记父目录是非 Git 项目。按新的 preflight 规则应阻塞，不能复用父目录 projectId，也不能把仓库路径填入 projectId。

当前 `create_thread` 工具说明另有明确限制：新聊天用于用户明确请求的新任务；当前请求的委派子任务应使用多 agent 工具。Threadweave 的核心要求是真实聊天 worker，不能违反该约束，也不能用临时 subagent 冒充。因此本次没有创建、消息派发或归档任何 worker 聊天，也没有创建 heartbeat 或 managed worktree。

两个阻塞独立存在：仅登记仓库不会消除宿主的聊天子任务限制。需在明确允许真实 worker 聊天的宿主中完成端到端验证。
