`create_thread` schema 没有 timeout 参数；本次调用本身约 1.4 秒返回 `clientThreadId`。宿主工作区创建也未出现可受控超时。因此**没有把运行等待超时冒充为 create API 超时**。

#### 取消

宿主没有暴露独立线程 cancel API。使用 `send_message_to_thread` 发送取消后返回：

```json
{"threadId":"01a1ce56-2cea-7b20-a8cb-87b20b52b06a"}
```

但 `read_thread` 的真实执行顺序显示：

1. 创建 partial 文件。
2. 执行 `sleep 60`，命令耗时 `59864ms`。
3. 命令自然结束后才处理取消消息，追加 `CANCELLED_BY_USER 2026-11-12`。
4. turn 最终 `completed`，线程 `idle`，final answer 为 `STOPPED_AFTER_CANCEL`。

因此当前宿主的“取消”是 turn 边界 steering，不是立即终止当前命令或进程。不能宣称发送取消即停止；停止证据必须以后续 state/idle/turn 完成和产物检查为准。

### P0-2.8 attach_worktree / archive_worktree 受支持路径

#### 创建与 attach

创建临时 managed worktree 返回：

```json
{"type":"created","worktreeGitRoot":"/Users/luzhentian/.codex/worktrees/p02-worktree-lifecycle/codex-threadweave","worktreeWorkspaceRoot":"/Users/luzhentian/.codex/worktrees/p02-worktree-lifecycle/codex-threadweave","registrationError":null}
```

对同一路径调用 `attach_worktree` 返回同样的 `created` 结构，说明当前任务对自身 managed worktree 的 attach 是幂等可用的。直接 Git 复核：

官方 OpenAI Docs 也确认 managed worktree 默认使用 detached HEAD：<https://learn.chatgpt.com/docs/environments/git-worktrees>。

#### archive 成功路径

为让第一个测试 worktree 变成非 primary，创建第二个 managed worktree 后，对第一个调用 `archive_worktree`，真实返回：

```json
{"type":"queued"}
```

随后验证：

- 第一个 worktree 路径已不存在。
- `list_artifacts` 出现 `attachmentType=archived_worktree`。
- `git worktree list --porcelain` 只剩主 checkout 和第二个 worktree。

这证明“非 primary 的当前任务 managed worktree”存在可用的 host archive 路径。

#### archive 限制

对仍为当前任务 primary checkout 的第二个 managed worktree 调用 `archive_worktree`，真实返回：

```text
The task's primary checkout cannot be removed.
```

对 worker task 拥有的 worktree 从 leader 调用，真实返回：

```text
This worktree is not attached to the current task.
```

尝试 `attach_worktree` 同一 worker-owned worktree，返回：

```text
This worktree is owned by another task.
```

因此 host API 的能力边界是：

- 当前任务、非 primary 的 managed worktree：可 archive。
- 当前任务 primary checkout：拒绝 archive。
- 其他 task 拥有的 worktree：leader 不能 attach/archive。
- 无独立 detach / 切回 Local 的线程工具；`attach_worktree` 会把当前任务 cwd 切到该 worktree，随后该 worktree 会被视为 primary。

#### 清理与残留

第二个测试 worktree 因 primary archive 被拒绝，先按安全条件非强制 `git worktree remove`；沙箱首次返回 `Operation not permitted`，显式授权后命令成功。第一测试 worktree 已 restore 并重新 attach，用于确认恢复路径：


当前仍保留一个干净、detached 的 managed worktree：

```text

```

`list_threads` 同时返回本 leader thread 的 `cwd=/Users/luzhentian/.codex/worktrees/p02-worktree-lifecycle/codex-threadweave`，直接证明 `attach_worktree` 已把当前任务工作区切到该路径。`archive_worktree` 明确拒绝删除 primary checkout，且当前线程控制面没有 detach/切回 Local 工具。为避免中断当前执行或删除活动 cwd，本轮保留该资源并在待办清单标记后续清理条件。

| 能力 | 结论 | 真实证据 |
