# O12 失败归因与恢复建议验收记录

日期：2026-11-13。Run：`20261113-o12-failure-01`。

## 结论

O12 已实现统一失败归因：错误记录可携带 `source`、`stage`、`resultCertainty`、`retryable`、`recommendation` 和可选证据字段。未知结果强制不可重试并建议先核对；进程类来源只有在存在明确进程证据时才能使用。

同时完成真实响应复核：复用已有真实 create/handoff/进程终止证据，按 O12 规则重新分类；未真实暴露的 create 超时、发送结果未知和“wait 超时等于进程退出”明确记录为不可观察。本轮没有新建真实聊天，也没有调用宿主工具。

## 实现

- 新增 `scripts/failure.py`：
  - 合法来源：`provider`、`host_api`、`supervisor_process`、`workspace_setup`、`model_output`、`acceptance`、`worker_process`、`unknown`。
  - `resultCertainty`：`confirmed_failure`、`unknown`。
  - `unknown` 或未知结果错误码会强制 `retryable=false`，建议 `reconcile_result`。
  - `worker_process` / `supervisor_process` 缺少显式 `evidence` 时构造失败记录直接拒绝。
  - 同一来源可因 code/阶段得到不同建议，例如认证失败要求核对凭据，限流允许在 leader 决策后按退避重试。
- `Controller.record_failure` 持久化统一失败记录，不执行重试或恢复。
- `create_worker` 超时现在记录为 `host_api / create_timeout / unknown / retryable=false / reconcile_result`，同时保留原始错误信息。
- 通用派发异常会记录 `dispatch_result_unknown`；来源无法确认时使用 `unknown`，不把线程超时推断成进程退出。
- `recovery.py` 在存在 unknown 或要求先核对的未解决失败时返回 `revalidate`，不会直接建议 recreate。
- `next_actions.py` 输出 `unresolvedFailures`，并把匹配 worker 的失败摘要附加到恢复建议。
- `references/state.schema.json` 增加可选字段，旧错误记录缺少这些字段仍可读取和校验。

## 建议规则

| 场景 | 默认建议 | 是否可直接重试 |
| --- | --- | --- |
| 认证失败 | 核对凭据 | 否 |
| 限流 | leader 决策后按退避重试 | 仅明确允许时 |
| 模型、reasoning、分支或 project 校验失败 | 修正请求后重试 | 否，先修正 |
| create/send 结果未知 | 先核对宿主结果 | 否 |
| 环境准备失败 | 核对幂等性后重新准备 | 条件式 |
| 模型输出不合格 | 重发请求或对现有 worker 返工 | 否，重派需审批 |
| 独立验收失败 | 修复后重新验收 | 否 |
| worker/supervisor 进程失败 | 保全成果并核对进程证据 | 否 |

`retryable=true` 只表示错误类型可能允许重试，不构成重试授权；结果未知一律先用宿主证据核对。
