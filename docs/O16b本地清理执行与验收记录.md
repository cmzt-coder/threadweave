## 功能节点与触发条件

| 节点 | 触发条件 | 行为 |
| --- | --- | --- |
| 预览 | 提供 declaration，未指定 `--execute` | 直接读取 Git 和外置证据，输出包含 fingerprint 的只读计划 |
| 身份检查 | 每次预览或执行 | canonical 路径、注册 worktree、common-dir、branch、HEAD 必须匹配 |
| 资源保护 | primary、当前 cwd 或其父路径、locked/shared、未注册、symlink 路径 | 拒绝 |
| 成果保护 | tracked/untracked/ignored 文件、未合入指定 integration ref | 拒绝 |
| 验收与报告 | 外置报告 SHA、HEAD 绑定的验收与归属声明均通过 | 允许继续检查；报告和证据须在目标目录外 |
| 停止检查 | `executionKind=local_git` | 无宿主聊天身份且本地进程已停止 |
| 停止检查 | `executionKind=host_thread` | 显式 threadId，leader 记录 idle/final/noActiveTurn 三项均为 true |
| 时效检查 | 停止/验收证据距离当前时间 0–300 秒 | 超时、未来时间或缺失字段均拒绝 |
| 执行门禁 | `--execute --approved-plan` | 对批准计划本身及当前重建计划重新计算 fingerprint；不一致拒绝 |
| 实际清理 | 所有检查通过且显式执行 | 非强制删除单个 worktree，保留分支和外置证据；Git 失败则报 blocked |

新入口使用包含路径、HEAD、integration HEAD 和证据字节 SHA 的精确计划，不能直接将旧 `cleanup-plan` 的分类 fingerprint 当成批准计划。

## 使用方法

从仓库目录运行，declaration、plan、报告和证据均放在目标 worktree 外：

```sh
python3 scripts/cleanup_apply.py /absolute/path/declaration.json > /absolute/path/approved-plan.json
python3 scripts/cleanup_apply.py /absolute/path/declaration.json \
  --approved-plan /absolute/path/approved-plan.json --execute
```

完整 declaration 与 evidence 示例见本地 `.threadweave/20261116-o16b-apply-01/declaration.json`、`stop-and-acceptance.json`。declaration 必需字段为 runId、repository、worktree、branch、head、integrationRef、report、reportSha256、evidence。evidence 必须绑定相同 runId/worktree/branch/head/reportSha256，并包含 observedAt、ownedByRun=true、shared=false、acceptanceVerified=true、executionKind 和对应 stop 证据。

停止、共享和验收声明是 leader 的可信输入，不是宿主签名，也不代替即时宿主查询。外部进程在重验后并发修改资源仍有竞态；本入口适用于已停止并隔离的专用本地 worktree。Git 自身的非强制检查是最后一道保护，不宣称跨宿主事务或原子删除。
