# O16 清理证据身份绑定修复记录

日期：2026-11-16。本轮继续现有功能的本地修复，不修改外部业务仓库，不新增宿主聊天、不推送。

## 发现问题与复现

原 `recheck_managed_cleanup` 检查宿主停止回执与附件所有者是否匹配传入的 owner_thread_id，但没有将其与 `cleanup_apply.preview` 实际读取的证据文件中的 threadId、executionKind 交叉核对。

触发条件：同一清理目标的证据文件声明 thread-a，而停止与附件 fixture 均声明 thread-b，调用方传入 thread-b。原逻辑可进入归档适配器。另一个同源缺口是 local_git 停止声明也可能与宿主回执组合使用。

新增测试先在修复前执行，`cross-thread-stop-cannot-authorize` 断言失败，复现了上述放行。测试使用真实临时 Git 仓库与显式宿主回执 fixture，归档适配器为 Mock；没有实际归档宿主资源。

## 功能节点及触发条件

| 节点 | 触发条件 | 修复后行为 |
| --- | --- | --- |
| 清理计划生成 | preview 完成 Git、报告与停止声明核验 | version=2，将同一次读取证据的 executionKind/threadId 纳入指纹 |
| 宿主归档身份联检 | 本地计划通过后、归档适配器调用前 | executionKind 必须为 host_thread，threadId 必须与宿主停止目标和附件 owner 一致 |
| 本地进程证据混入 | 计划为 local_git | blocked，归档适配器调用次数为零；本地清理入口仍可使用 local_git |
| 跨聊天证据混入 | 计划 threadId 与宿主目标不同 | blocked，保留 worktree、报告和证据 |
| 异常宿主观察 | metadata/result、poll、status、附件 payload 等结构不符，或时间缺失 | 返回结构化 blocked；不因 AttributeError 中断门禁，不调用归档 |
| 旧批准计划 | version=1 或缺少新增字段，即使重新计算自身指纹 | 与当前即时计划不同，拒绝执行，要求重新预览和批准 |
| 全部本地联检通过 | 精确身份、停止、所有权和计划一致 | 进入宿主适配器；请求结果仍不等于资源删除，保留完成核验要求 |

原有 30 秒宿主观察时效、300 秒证据时效、非 primary/shared、干净且已合入、报告外置以及禁止本地删除回退等约束保持有效。
