## 第一批：核心回归修复

- [x] **T01 派发结果核对恢复**
  - 问题：`resolvedAt` 未在 schema 声明；`resolve_dispatch` 只改 intent，不同步 worker 状态。
  - 建议：按 sent/not_sent/unknown 分别推进 dispatched、保持 ready、保持未决；核对记录可持久化。
  - 验收：发送异常 → 从磁盘恢复 → 核对 → 继续观察或受控重试，零重复任务。

  - 进展（2026-11-12）：schema 增加 resolvedAt；resolve_dispatch 按 sent/not_sent/unknown 同步 worker 状态并保存核对记录。
- [x] **T02 有效 worker 与完成规则**
  - 问题：历史 cancelled attempt 阻塞 complete；直接 dispatch 旧 attempt 仍可发送。
  - 建议：完成校验只要求当前有效 attempt 已集成/归档；正式派发只接受当前选定 attempt；历史 attempt 参与停止/清理审计。
  - 验收：a#1 失败保全 → a#2 完成集成 → 清理 → complete；旧 attempt 迟到请求不能改变结果。

  - 进展：完成态只检查当前有效 attempt；历史 cancelled 不阻塞 complete；dispatch 只接受当前有效 attempt。
- [x] **T03 worktree 身份不可绕过**
  - 问题：`expected.worker_root` 可省略；未来时间能通过年龄检查。
  - 建议：从持久 `worker.worktree` 自动生成预期 root；拒绝缺失/未登记 root、未来时间和无效时间。
  - 验收：省略 expected.worker_root 也不能绕过精确目录比较；未来时间零任务消息。

  - 进展：expected.worker_root 从持久 worker.worktree 生成；缺 worktree、未来时间和未登记 root 均拒绝。
- [x] **T05 阶段化停滞与恢复**
  - 问题：旧 graceDeadline 优先于新进展；running 仍按初始化超时；running/blocked 恢复用 HEAD == base。
  - 建议：先判断新进展是否撤销旧宽限；初始化预算只作用于初始化状态；执行阶段允许经核验的正常提交。
  - 验收：长任务不被初始化超时干扰；新进展取消旧宽限；执行中断且有提交时可进入核验恢复。

## 第二批：集成验收链

  - 进展：新进展撤销旧 graceDeadline；初始化预算只作用于初始化状态；running/blocked 恢复允许经核验的正常提交。
- [x] **T04 报告 → leader 审查 → 串行集成验收链**
  - 问题：reported 可直接 integrated；cleanup_pending 仍可派发；缺 authorization 仍可 create。
  - 建议：报告身份/SHA/任务修订核对；集成前 branch tip/base 祖先/cleanup 检查；记录每次集成前后 SHA、审查结论与验证结果；按六阶段约束外部动作。
