# O16 归档授权信封记录

日期：2026-11-17。范围：把批准的 Git 清理计划、停止回执、归档前活动附件、预期 archive request 和授权窗口绑定成单一本地 fingerprint。结论：本地授权绑定通过；仍未获得宿主签名身份，也未接入删除放行条件。

## 目标

在真实归档前生成一个可复核信封，要求以下证据同时成立：

```text
approved cleanup plan
+ stop receipt
+ Git/worktree plan
+ active pre-archive attachment
+ expected archive request SHA
+ explicit local authorization window
→ authorizationFingerprint
```

该 fingerprint 用来发现计划漂移、停止证据变化、附件变化、请求变化和授权过期；它不是用户签名，也不是宿主签名。

## 功能节点与精确触发条件

| 节点 | 必须满足 | 阻断条件 |
| --- | --- | --- |
| 计划复核 | `cleanup_apply.preview` 当前计划 fingerprint 等于批准计划 | 计划漂移、批准 fingerprint 不匹配、plan 非 host_thread |
| 任务绑定 | runId/role/attempt/taskRevision 精确一致 | worker 绑定缺失或变化 |
| 停止回执 | source=desktop_tool_bridge、精确 thread、idle、completed turn、final answer、0–30 秒内 | active、旧回执、未来回执、非 final |
| 归档前附件 | 当前 local worktree payload 精确匹配资源身份 | archived、错误 root/host/workspace、过期 |
| 授权窗口 | authorizedAt < now < expiresAt，TTL 1–300 秒 | 过期、未来、窗口过长、证据晚于授权 |
| archive request | request SHA256 显式提供并由调用方绑定 | 非法 SHA、未绑定请求 |
| nonce | 显式且长度受限 | 缺失或过长 |
| 信封复算 | canonical envelope 的 SHA256 等于 `authorizationFingerprint` | 信封任意字段被篡改或任一输入变化 |

## 输出

成功时输出：

- `status=envelope_prepared` 或 `envelope_verified`
- `localAuthorizationBindingVerified=true`
- `authorizationFingerprint=<sha256>`
- `cleanupEligible=false`
- `deletionPerformed=false`
- `hostSignedIdentityVerified=false`
- `userApprovalCryptographicallyVerified=false`

信封包含：

- cleanup plan fingerprint 和 evidence SHA256
- integration HEAD
- stop receipt SHA256
- pre-inventory receipt SHA256
- archive request SHA
- threadId
- worktree identity
- run/role/attempt/taskRevision
- authorization nonce 和有效时间

## 接口

```sh
# 构建
python3 scripts/archive_authorization.py build manifest.json

# 使用同一证据复算/验证
python3 scripts/archive_authorization.py verify manifest.json --envelope result.json
```

`build` 只读，不调用宿主、不写数据库、不删除资源。`verify` 在任一输入变化时返回 blocked。

## 安全边界

- `authorizedAt` 和 nonce 是本地输入，不等于用户签名；
- `archiveRequestSha` 只绑定请求哈希，不证明宿主已批准；
- 当前输出不证明 pre/archive/post 来自同一宿主身份；
- 当前信封尚未接入 `execute_managed_cleanup` 删除路径；
- 只有本地代码哈希和时间窗口，不能抵抗恶意本地写入者。

## 只读完成观察集成

`scripts/host_archive_guard.py` 已支持可选 `authorization` 输入：

- `requireAuthorization=true` 时缺失信封直接 blocked；
- 校验 authorization pre-inventory operation、request SHA 和 tool-result SHA 与 provenance 一致；
- 使用归档账本的 `observedAt` 调用 `verify_envelope_for_archive`，要求授权窗口覆盖真实 archive 时间；
- 校验 envelope 的 binding、worktree、threadId 和 archiveRequestSha 与 guard 输入一致；
- 成功后输出 `authorizationBindingVerified=true` 和 authorization fingerprint；
- 仍保持 `cleanupEligible=false`、`hostSignedIdentityVerified=false`，不接入执行放行。

该集成使用受控 fixture 验证；真实正向归档发生在授权信封实现前，没有可回填的预归档信封，不能把历史正向操作伪造成已由该信封批准。

## 显式 opt-in 执行路径

新增 `scripts/host_guarded_cleanup.py` 的 `execute_host_guarded_cleanup`：

- 必须 `authorized=true`；
- authorization declaration 和 approved plan 必须与调用输入一致；
- stop receipt、pre-inventory receipt 的 canonical digest 必须一致；
- `owner_thread_id` 必须等于 approved plan 的 `threadId`；
- `verify_envelope` 必须成功；
- expected archive request SHA 必须等于授权信封中的 SHA；
- 只有上述条件全部通过才调用 `adapter.archive_worktree`；
- 结果仍要求 `host_archive_guard` 做归档后完成复核，且 `cleanupEligible=false`。

默认 `execute_managed_cleanup` 未修改，仍要求已有严格所有权字段和门禁。该 opt-in 路径是 O16 的执行路径实现，不扩大默认删除授权。
